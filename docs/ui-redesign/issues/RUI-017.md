## Integration points

- Existing: src/main.ts telemetry formatting/sparkline
- New: src/ui/components/TelemetryCard.ts

## Implementation tasks

- [ ] Project X/Z meters, yaw degrees, planar speed, signed yaw rate and possession.
- [ ] Use missing-data states; omit battery and do not invent jaw status.
- [ ] Sample a bounded per-selected-slot history at 10 Hz and update DOM only for changed values.
- [ ] Add text alternatives and avoid live-announcing every numerical frame.

## Acceptance criteria

- [ ] Values match authoritative getters within documented formatting precision.
- [ ] Slot/session change cannot reuse mislabeled history; negative zero is normalized only for display.
- [ ] DOM sampling is bounded and does not allocate a growing array every frame.

## Test evidence required

- [ ] New tests/telemetryView.test.ts for units, missing values, wrap boundary and sample caps.
- [ ] Browser: drive/stop/select robot and compare visible values against observed core state.
- [ ] Attach actual source SHA, command/output or review artifact, and any blocked checks. Do not claim execution from source inspection.

## Boundaries and completion

Preserve authoritative simulation, match, replay and Worker contracts. Views do not manipulate physics directly. New manual interactions must use the approved input/command path. Do not add unsupported battery, weather, lift, account or official-arena claims to match the illustration.
