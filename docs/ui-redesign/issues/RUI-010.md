## Integration points

- Existing: src/main.ts setActiveSlot
- New: src/ui/components/RobotSelector.ts

## Implementation tasks

- [ ] Render actual active slots and bounded names with role/team badges and robot silhouettes.
- [ ] Select atomically across telemetry, script/editor context, manual source and follow target.
- [ ] Clear old held input; require a new input press after switching.
- [ ] Support sparse slot IDs and no-robot state without modulo assumptions in the view.

## Acceptance criteria

- [ ] Baseline R1 remains Red and R2 Blue even though selected tiles use the primary blue accent.
- [ ] No movement command leaks from an old held pointer/key to the new robot.
- [ ] Follow mode persists while its target changes, unless explicitly disabled by camera action.

## Test evidence required

- [ ] Unit: sparse IDs, removed slot, missing spec and long names.
- [ ] Browser: click each card while a key/pointer is held; inspect old/new command ownership.
- [ ] Attach actual source SHA, command/output or review artifact, and any blocked checks. Do not claim execution from source inspection.

## Boundaries and completion

Preserve authoritative simulation, match, replay and Worker contracts. Views do not manipulate physics directly. New manual interactions must use the approved input/command path. Do not add unsupported battery, weather, lift, account or official-arena claims to match the illustration.
