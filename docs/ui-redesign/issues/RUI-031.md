## Integration points

- Existing: render loop and telemetry updates
- New: docs/ui-redesign/evidence/performance.md

## Implementation tasks

- [ ] Compare the same scene/machine/browser at baseline and candidate for 30 seconds after warm-up.
- [ ] Record p50/p95 frame time, UI update cost, heap trend and WebGL/Worker/subscription counts.
- [ ] Cycle panels/slot changes/fullscreen repeatedly and verify disposal/bounded buffers.
- [ ] Optimize projection frequency/layout reads rather than changing solver behavior to hit UI metrics.

## Acceptance criteria

- [ ] Proposed p95 frame-time overhead target is ≤15% over the recorded baseline or has a measured accepted exception.
- [ ] One renderer and the expected bounded Worker count remain after 50 UI cycles.
- [ ] No runtime debug log fires per tick; telemetry/history/error output is bounded.

## Test evidence required

- [ ] Browser profiling on declared reference hardware; record software-rendered CI separately.
- [ ] Resource-leak test with mount/dispose cycles and delayed async operations.
- [ ] Attach actual source SHA, command/output or review artifact, and any blocked checks. Do not claim execution from source inspection.

## Boundaries and completion

Preserve authoritative simulation, match, replay and Worker contracts. Views do not manipulate physics directly. New manual interactions must use the approved input/command path. Do not add unsupported battery, weather, lift, account or official-arena claims to match the illustration.
