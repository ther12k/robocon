## Summary

The pictured quick actions include unsupported lift controls and a selected-robot reset that cannot safely call whole-world or whole-team reset.

## Integration points

- Existing: src/core/SimulationCore.ts respawn helpers, src/sim/robot/GripperController.ts
- New: guarded selected-slot reset operation and QuickActionsCard.ts

## Implementation tasks

- [ ] Show Grab/Release based on module and possession; label missing module explicitly.
- [ ] Add a narrowly scoped selected-slot reset inside the domain with documented held-object release semantics.
- [ ] Allow reset only in idle practice with no capture/playback and no selected-slot script.
- [ ] Replace lift actions with supported Reset View/help actions rather than decorative enabled buttons.

## Acceptance criteria

- [ ] Reset does not reset core time, score, opponents, arena configuration or unrelated object transforms.
- [ ] Reset during match/recording/playback is denied by facade even if dispatched programmatically.
- [ ] UI never claims jaw open/closed or lift height when no model exists.

## Test evidence required

- [ ] Unit: two same-team robots prove selected reset is not team-wide; held ownership remains consistent.
- [ ] Browser: quick-action states with installed/missing gripper and illegal reset attempts.
- [ ] Attach actual source SHA, command/output or review artifact, and any blocked checks. Do not claim execution from source inspection.

## Boundaries and completion

Preserve authoritative simulation, match, replay and Worker contracts. Views do not manipulate physics directly. New manual interactions must use the approved input/command path. Do not add unsupported battery, weather, lift, account or official-arena claims to match the illustration.
