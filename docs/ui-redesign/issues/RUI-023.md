## Integration points

## Implementation tasks

- [ ] Route file input through byte limits and the bounded parser before UI adoption.
- [ ] Separate parsed, compatible and fully verified states.
- [ ] Validate compatibility before resetting an ended match or replacing a previous valid artifact.
- [ ] Use request tokens so stale file-reader completions do not replace a later selection.

## Acceptance criteria

- [ ] Oversized/malformed input produces bounded errors and no application freeze.
- [ ] Rejected import leaves valid previous replay, score, winner and applied specs unchanged.
- [ ] No filename or replay metadata is rendered as HTML.

## Test evidence required

- [ ] Unit: parser budget, oversized arrays, stale async file load and unknown metadata.
- [ ] Browser: invalid JSON, wrong build/config and malicious engine/file-name text through real file input.
- [ ] Attach actual source SHA, command/output or review artifact, and any blocked checks. Do not claim execution from source inspection.

## Boundaries and completion

Preserve authoritative simulation, match, replay and Worker contracts. Views do not manipulate physics directly. New manual interactions must use the approved input/command path. Do not add unsupported battery, weather, lift, account or official-arena claims to match the illustration.

A completed PR names this planning ID and its real GitHub issue number, records any intentional deviation, and links its evidence. Numeric IDs are assigned only when issues are actually registered.
