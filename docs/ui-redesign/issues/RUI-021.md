The layout refactor must not lose tick/session guards, backpressure, sync contract or visibility behavior that the newer baseline introduced.

## Integration points

- Existing: src/core/autonomy.ts, src/core/browserHost.ts, visibility handler
- New: focused UI integration tests

## Implementation tasks

- [ ] Verify matching session/tick command admission through the facade without weakening existing checks.
- [ ] Preserve one outstanding Worker tick and source invalidation on world reset.
- [ ] Ensure UI visibility/panel changes do not accidentally kill a healthy idle Worker or restart it.
- [ ] Expose recoverable failure with Stop/Retry workflow; remove per-tick debug logs from production paths.

## Acceptance criteria

- [ ] A late old-session reply cannot mutate the current world or its UI status.
- [ ] Promise-returning and stale-ID callbacks fail with actionable text and no undead control source.
- [ ] Repeated recovery does not leak Workers or subscriptions.

## Test evidence required

- [ ] Unit/integration: old ID while new tick open, old session response, sync rejection and stall boundary.
- [ ] Browser with actual Worker: Run → error → revise → Run; visible/hidden transition sanity.
- [ ] Attach actual source SHA, command/output or review artifact, and any blocked checks. Do not claim execution from source inspection.

## Boundaries and completion

Preserve authoritative simulation, match, replay and Worker contracts. Views do not manipulate physics directly. New manual interactions must use the approved input/command path. Do not add unsupported battery, weather, lift, account or official-arena claims to match the illustration.
