# [RUI-042] Plan capability isolation for untrusted scripts independently of the UI

**Issue ID:** `RUI-042`
**Scope:** `deferred`
**Priority:** `P3`
**Milestone:** `M5 - Deferred capabilities`
**Estimate:** `L` — relative effort, not a calendar commitment
**Labels:** `project:robocon-light-ui`, `type:security`, `area:security`, `priority:p3`, `scope:deferred`
**Depends on:** `RUI-001`, `RUI-002`, `RUI-021`
**Requirements:** `FR-10`, `NFR-03`

## Summary

Native Workers provide thread isolation but not the trusted capability boundary needed for arbitrary third-party code. This is a separate engineering/security gate, not a theme change.

## Source grounding

Planning baseline: `f5092ffa5aa8eeb9aaab016dfa4b8a303c14c12a`. [S16](https://github.com/ther12k/robocon/blob/f5092ffa5aa8eeb9aaab016dfa4b8a303c14c12a/src/core/autonomy.ts) [S02](https://github.com/ther12k/robocon/blob/f5092ffa5aa8eeb9aaab016dfa4b8a303c14c12a/index.html#L9-L99)

This issue describes proposed work. Re-check the implementation checkout before treating a gap as current; do not reintroduce or duplicate already-landed audit fixes.

## Integration points

- Future: isolated runtime/host boundary, threat model and adversarial test suite

## Implementation tasks

- [ ] Define trusted/untrusted product modes and threat model, including network/storage/resource access.
- [ ] Evaluate a capability VM such as QuickJS/WASM or an equivalent constrained runtime with explicit host APIs.
- [ ] Specify CPU/memory/time budgets, termination, no ambient network and source/tick/session provenance.
- [ ] Require independent security review before removing trusted-code-only warnings or enabling untrusted execution.

## Acceptance criteria

- [ ] UI launch does not imply this security work is complete.
- [ ] A later untrusted mode cannot access undeclared host capabilities in adversarial tests.
- [ ] Residual risks, limitations and operational behavior are documented honestly.

## Test evidence required

- [ ] Future adversarial suite for network/storage escape, resource exhaustion and protocol abuse.
- [ ] Independent review evidence required before public untrusted-code claims.
- [ ] Attach actual source SHA, command/output or review artifact, and any blocked checks. Do not claim execution from source inspection.

## Boundaries and completion

This is **not a dependency of the light-dashboard launch**. Keep its related affordance omitted or explicitly unavailable until an independently approved implementation and evidence exist. Feasibility/design findings are not implementation completion.

A completed PR names this planning ID and its real GitHub issue number, records any intentional deviation, and links its evidence. Numeric IDs are assigned only when issues are actually registered.
