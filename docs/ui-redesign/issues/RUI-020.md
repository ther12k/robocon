## Integration points

- New: src/ui/components/AutonomyCard.ts

## Implementation tasks

- [ ] Render status card and editable script panel with actual selected slot.
- [ ] Load .js into a draft only; Run is a separate explicit action.
- [ ] Keep synchronous callback and trusted-code messages prominent; render logs as text.
- [ ] Wire Run/Stop/Take Manual Control through capability and ownership checks.

## Acceptance criteria

- [ ] Opening/loading a script never executes it.
- [ ] Script error details are escaped and bounded; active slot identity remains clear.
- [ ] Start is denied during playback/capture or disallowed match phases while Stop remains reachable when appropriate.

## Test evidence required

- [ ] Browser: load, edit, Run, Stop and malicious log payload through real controls.
- [ ] Unit: draft/source-state transitions, file-size rejection and unavailable slot.
- [ ] Attach actual source SHA, command/output or review artifact, and any blocked checks. Do not claim execution from source inspection.

## Boundaries and completion

Preserve authoritative simulation, match, replay and Worker contracts. Views do not manipulate physics directly. New manual interactions must use the approved input/command path. Do not add unsupported battery, weather, lift, account or official-arena claims to match the illustration.

A completed PR names this planning ID and its real GitHub issue number, records any intentional deviation, and links its evidence. Numeric IDs are assigned only when issues are actually registered.
