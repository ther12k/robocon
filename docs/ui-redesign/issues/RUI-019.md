## Summary

Match screens should use the chosen light language and preserve results through replay attempts rather than introduce a separate dark product.

## Integration points

- Existing: src/core/match.ts, src/main.ts scoreboard/result handlers
- New: src/ui/components/MatchResultPanel.ts

## Implementation tasks

- [ ] Render Red/Blue scores, configured retry denominator, phase timer and winner/draw.
- [ ] Show a bounded event-log view without consuming domain entries.
- [ ] Associate export/replay actions only with a recording of the current match; label prior artifacts separately.
- [ ] Preserve results on invalid/incompatible load; route compatible ended replay through the facade.

## Acceptance criteria

- [ ] Setup/countdown/play/ended each has correct controls and text.
- [ ] Unrecorded completed match cannot pretend a replay exists.
- [ ] Post-whistle domain neutralization remains evidenced; view changes do not alter final score.

## Test evidence required

- [ ] Browser: complete a short deterministic fixture match and inspect result actions.
- [ ] Unit/integration: incompatible replay leaves score, winner, log and state unchanged.
- [ ] Attach actual source SHA, command/output or review artifact, and any blocked checks. Do not claim execution from source inspection.

## Boundaries and completion

Preserve authoritative simulation, match, replay and Worker contracts. Views do not manipulate physics directly. New manual interactions must use the approved input/command path. Do not add unsupported battery, weather, lift, account or official-arena claims to match the illustration.

A completed PR names this planning ID and its real GitHub issue number, records any intentional deviation, and links its evidence. Numeric IDs are assigned only when issues are actually registered.
