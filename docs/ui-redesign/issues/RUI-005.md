## Summary

A re-skin can accidentally enable illegal transitions. Button state and command execution must share a single policy while preserving the existing core locks.

## Implementation tasks

- [x] Implement the action matrix with reason codes for boot/match/replay/source/panel conditions.
- [x] Extract Start Match, recording, playback preparation, Builder Apply and selected-slot quick actions behind the facade.
- [x] Validate and check admission before world/result changes; preserve last valid artifacts on rejection.
- [x] Add pending request IDs for async import/copy operations; stop duplicate actions.

## Acceptance criteria

- [x] Disabled controls and programmatic dispatch return the same denial reason.
- [x] Illegal mutations leave specs, score, winner, capture owner and loaded replay unchanged.
- [x] An ended compatible replay is admitted only after compatibility passes; incompatible files do not clear results.
- [x] No controller method bypasses core input or replay validation.

## Test evidence required

- [x] New tests/uiCapabilities.test.ts table-tests every matrix intersection.
- [x] Integration tests invoke the facade directly and compare authoritative before/after state.
- [x] Attach actual source SHA, command/output or review artifact, and any blocked checks. Do not claim execution from source inspection.

## Boundaries and completion

Preserve authoritative simulation, match, replay and Worker contracts. Views do not manipulate physics directly. New manual interactions must use the approved input/command path. Do not add unsupported battery, weather, lift, account or official-arena claims to match the illustration.
