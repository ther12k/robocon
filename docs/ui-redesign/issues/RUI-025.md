## Summary

Share must be reachable from the actual UI and survive new navigation state without conflating copying with cloud upload.

## Integration points

- Existing: src/core/replayShare.ts, src/main.ts copy/hash handlers
- New: selectable clipboard-fallback component

## Implementation tasks

- [ ] Bind enablement to valid artifact and transport ownership in the capability layer.
- [ ] Use existing bounded payload encoder/decoder and reserve #r= fragment.
- [ ] Provide an accessible selectable fallback instead of relying only on a blocking prompt.
- [ ] Handle clipboard timeout, oversized link and fresh boot with pending import.

## Acceptance criteria

- [ ] Actual Copy Link button enables/disables correctly before/during/after recording and playback.
- [ ] Fresh-page shared file loads only after ready; it does not auto-execute code or reset an active session.
- [ ] Link UI states that payload is local/in the URL, not a hosted private upload.

## Test evidence required

- [ ] Browser: real click, clipboard denied fallback and open returned URL in a new page.
- [ ] Unit: encoded/decompressed size limits and outdated async copy result handling.
- [ ] Attach actual source SHA, command/output or review artifact, and any blocked checks. Do not claim execution from source inspection.
