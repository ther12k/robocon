# [RUI-018] Present session status and explicit arena provenance

**Issue ID:** `RUI-018`
**Scope:** `launch`
**Priority:** `P1`
**Milestone:** `M2 - Live practice and match workspace`
**Estimate:** `M` — relative effort, not a calendar commitment
**Labels:** `project:robocon-light-ui`, `type:feature`, `area:telemetry`, `priority:p1`, `scope:launch`

## Summary

Users need to know which timeline they are watching and whether the arena is provisional, without mistaking static labels for new simulated systems.

Planning baseline: `f5092ffa5aa8eeb9aaab016dfa4b8a303c14c12a`. [S10](https://github.com/ther12k/robocon/blob/f5092ffa5aa8eeb9aaab016dfa4b8a303c14c12a/src/core/match.ts) [S12](https://github.com/ther12k/robocon/blob/f5092ffa5aa8eeb9aaab016dfa4b8a303c14c12a/public/arenas/default.json#L1-L39)

## Integration points

- Existing: arena.meta and match getters
- New: src/ui/components/SessionCard.ts

## Implementation tasks

- [ ] Render Practice/Match/Replay mode and real phase with an appropriate clock.
- [ ] Show actual arena name, config provenance and a concise verification note.
- [ ] Use a truthful fixed-rate/light-setting label only if useful; omit weather and connection fiction.
- [ ] Expose an accessible details panel with version/build metadata without overwhelming the main card.

## Acceptance criteria

- [ ] Default arena never appears as officially verified or Standard official 2027.
- [ ] Clock is derived from the current domain timeline and does not drift from a UI setInterval.
- [ ] Empty or malformed optional provenance fails closed to Unknown/Provisional.

## Test evidence required

- [ ] Unit: all match/replay modes and official/draft/inferred/unknown metadata.
- [ ] Browser: transitions update text consistently with score and replay card.
- [ ] Attach actual source SHA, command/output or review artifact, and any blocked checks. Do not claim execution from source inspection.

## Boundaries and completion

Preserve authoritative simulation, match, replay and Worker contracts. Views do not manipulate physics directly. New manual interactions must use the approved input/command path. Do not add unsupported battery, weather, lift, account or official-arena claims to match the illustration.

A completed PR names this planning ID and its real GitHub issue number, records any intentional deviation, and links its evidence. Numeric IDs are assigned only when issues are actually registered.
