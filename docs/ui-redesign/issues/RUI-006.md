# [RUI-006] Implement panel lifetime and accessible focus ownership

**Issue ID:** `RUI-006`
**Scope:** `launch`
**Priority:** `P1`
**Milestone:** `M1 - Shell and integration seams`
**Estimate:** `M` — relative effort, not a calendar commitment

## Summary

Several cards open editors or drawers. Independently toggling UI focus can re-enable driving while another dialog still owns focus.

## Integration points

- Existing: src/main.ts panel handlers, src/ui/RobotBuilderPanel.ts
- New: src/ui/PanelManager.ts

## Implementation tasks

- [ ] Implement a single active-panel policy or tokenized panel stack with cleanup.
- [ ] Clear held manual input on panel open; restore focus to the invoker on close without re-arming held input.
- [ ] Provide dialog labels, focus trapping where modal, Escape behavior and background inertness.
- [ ] Make repeated opens idempotent; mounting a panel does not attach another renderer or reset the world.

## Acceptance criteria

- [ ] Closing nested Preferences does not release the underlying editor focus lock.
- [ ] Enter/Space on a button never also starts a match.
- [ ] Panel switches keep unsaved drafts or ask confirmation; Tab exits nonmodal regions normally.
